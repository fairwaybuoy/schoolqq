# 班讯 · QQ 班级通知日程助手

个人使用、简体中文、Asia/Shanghai、本机默认绑定。把通知文字/截图整理为报名截止、材料截止和活动场次，并提供原文核对、月/周日历、人工确认、版本记录和 ICS 快照。NapCat 连接状态与真实消息接收须在本机核对。

## Windows 统一入口与 NapCat WebUI

`windows/Start-All.cmd` 会检查 NapCat WebUI 和班讯，启动缺少的程序并打开统一入口。NapCat 暂不可用时会打开班讯。班讯默认端口 8080，可在 `.env` 设置 `PORT`。NapCat 优先使用 `NAPCAT_WEBUI_PORT`，其次读取安装目录 `config/webui.json` 的端口，最后使用 6099。启动器通过 WebUI 响应确认 NapCat 已就绪。若 NapCat 端口被其他程序占用，将打开班讯独立页面。NapCat 安装目录会从环境变量、`.env` 的 `NAPCAT_HOME` 和项目附近目录查找；如果路径不同，在 `.env` 加一行 `NAPCAT_HOME=你的 NapCat 安装目录`（包含 `napcat.mjs` 的文件夹）。QQ 登录与 OneBot token 仍沿用现有配置。

项目附带 `napcat-plugin-schoolqq` 页面插件，仅将班讯页面嵌入 NapCat WebUI 侧边栏，不另行接收或发送 QQ 消息。统一入口会在找到 NapCat 安装目录时将插件文件复制到其 `plugins` 目录。如果侧边栏没有加载新页面，重启已运行的 NapCat 一次。需要支持页面扩展的 NapCat 版本（上游文档为 ≥4.14.0）；若安装受插件白名单或版本限制，请保留独立班讯页面使用，不改写 NapCat 的安全配置。

在 NapCat WebUI 点击“班讯 · 核对与日程”即可打开班讯的核对列表。请用启动器打开的 127.0.0.1 地址。若班讯已通过原生入口单独启动，先关闭它再使用统一入口，或在 `.env` 设置 `NAPCAT_WEBUI_PORT` 后重启班讯。班讯仍由本机 Python 服务运行，首次登录继续使用 `.env` 的 `APP_TOKEN`。新“核对与整理”页显示自动提取的日期、证据和来源原文，用户确认后进入已确认日历；缺日期时先打开详情补充。该嵌入方式和统一启动脚本仍需在用户的 NapCat/Windows 版本上实测。

选型与相关 issue：[docs/selection.md](docs/selection.md)；实际调查 commit：[docs/upstream-review.json](docs/upstream-review.json)；源码来源与许可：[THIRD_PARTY.md](THIRD_PARTY.md)。未复用 qqbot 的耦合聊天工程：官方 NoneBot2 + OneBot 适配器，独立只读接收插件，不 fork 框架。

## 本机运行

从完整压缩包解压后，按 [Windows 使用说明](windows/使用说明.md) 启动。默认班讯地址为 http://127.0.0.1:8080/assistant/ 。第一次运行会创建本机配置，网页登录使用 `.env` 里的 `APP_TOKEN`。

可以先加载模拟样例，也可以在“添加通知”粘贴收到的通知或上传截图。核对日期和原文后，才会生成已确认的 ICS 日期。接收实时消息期间需保持程序运行。

## 真实 QQ 接入：还需你完成

NapCat 是基于 NTQQ 的**非官方接入**，可能触发登录风控、封禁或因协议变化中断；请阅读其限制性/混合许可。本工程不复制/修改其源码、不处理验证码绕过、不自动加群、不要求群管理员权限。QQ 官方机器人接口是另一条路线，不能据官方接口假定可读取普通账号的全部群消息。

1. 由你选择和安装符合上游许可的 NapCat 发行版，并扫码登录自己选择的 QQ 账号。尚未在本工程真实验证任何 NapCat release 的登录，不提供未经验证的 NapCat 安装命令。
2. 登录账号须已加入目标班级群，邀请由你完成。在本机 `.env` 设置 `GROUP_WHITELIST=群号1,群号2`，用英文逗号；重新启动助手。默认只有合成群 `demo-class`，不要把它当作真实群号。
3. 在 NapCat 的 OneBot v11 配置启用**反向 WebSocket**，本机原生助手地址 `ws://127.0.0.1:8080/onebot/v11/ws`；消息格式 array，关闭上报自己发出的消息，保留证书验证。`token` 与 `.env` 的 `ONEBOT_ACCESS_TOKEN` 一致，`X-Self-ID` 使用登录账号，官方适配器校验 Bearer token。参考配置见 `examples/onebot-reverse-ws.json`，其字段参照已审查上游配置，实际 NapCat 接入尚待验证。
4. 先看网页“数据与连接”：已连接不等于可读群消息。`账号群成员验证` 应在 `get_group_list` 成功后出现目标群为 true。
5. 请班级群成员发一条**普通、未 @ 机器人的群消息**。页面的普通消息探针应出现该群的消息 ID 和收到时间，且原文进入 SQLite。再发送实际通知，核对列表、日历与来源。不要只用 @ 对话验证。
6. 断线重连后再次测试普通群消息。到“数据与连接”选择真实 QQ 群，先点“读取最近历史”，再按“继续读取更早消息”逐批向前翻，单次最多 2000 条。旧消息按原发送顺序批量写入，重复消息会自动跳过；“全部”及“已截止 / 已结束”包含过去的比赛，也会展示投稿截止。NapCat / QQ 可能只返回部分历史，不能证明离线缺口全部补齐，也不恢复所有撤回消息。

合成探针通过完整官方适配器的反向 WS 入口，不是手工伪造业务函数成功；但合成协议响应仍不等于 NapCat/QQ 登录成功。代码没有 `send_msg`、群管理、主动发言或向班级群汇总/提醒功能。

## 五种消息入口与导入格式

- 实时：官方适配器 `GroupMessageEvent`，所有已配置群的普通消息均可接收，不要求 `to_me`，先入 SQLite 再异步提取。
- 历史：连接 NapCat 后在“数据与连接”手动选择白名单群与读取条数。服务端再核对当前账号是否为群成员，只读调用 `get_group_msg_history`，从新到旧分页，按 QQ 消息 ID 去重。“继续读取更早消息”从该账号该群已入库的最早 QQ 消息向前翻。一次最多 2000 条。翻页完成后统一入库，读取或写入失败可重试。历史可用范围由 NapCat / QQ 决定。
- 粘贴：网页填写来源群与**原消息发送时间**。发送时间必须有时区，由网页按上海时间转换，回放不能使用导入当天。
- JSON / JSONL：仅支持下面的工程格式，JSON 可为单对象或数组，JSONL 每行一个对象；每批 ≤500 条，≤2MB。不承诺兼容任意 QQ 历史导出格式。可用 `examples/messages.json`、`examples/messages.jsonl`。
- 截图：网页上传 PNG/JPEG/WebP，≤5MB、≤1600 万像素、本地 Tesseract 中文/英文 OCR，20 秒超时。失败可见且可重试。实时图片 URL 不自动抓取，请上传原截图补充。未支持附件显示“未解析”。

```json
{
  "account_id": "local",
  "group_id": "demo-class",
  "group_name": "模拟班级群",
  "message_id": "90071992547409931234",
  "sent_at": "2026-10-12T10:00:00+08:00",
  "source": "import",
  "text": "商赛 10 月 18 日 18:00 截止报名，10 月 25 日 14:00 比赛",
  "segments": [],
  "reply_to": null,
  "reply_text": null
}
```

QQ ID 和长数字 ID 在业务数据中以字符串保存。幂等键为账号、群和消息 ID；跨 ID 相同正文只有同账号同群才视为重复。引用可提供 `reply_to` 与实际得到的 `reply_text`；未提供时仅查本地已存消息，查不到明确标记缺失。NoneBot 上游可读取引用接口提供的内容；处理与记录使用 `original_message`，避免适配器移除 @ 后把 @ 消息误算普通消息探针。合并转发只处理实际提供的内联 `nodes/content`；没有节点不假造，也未启用未经真实验证的远程转发节点获取。参见 `examples/segments.json`。

## 配置、模型与数据边界

全部配置在 `.env.example`。`MODEL_BASE_URL` 是固定的 OpenAI 兼容 `/v1` 基址，`MODEL` 是模型名，`MODEL_API_KEY` 只在服务端使用，不进入网页。可以接本地兼容模型；未配置基址/模型时运行离线保守规则。真实模型费用、额度、有效 key 和抽取质量尚未外部验证，已通过合成模型响应检验 JSON、证据、超时错误路径与预算。

廉价筛选后只发送通知必要片段（最多 12000 字符）和同群同账号最近最多 5 个事件的有限标题/时间上下文，不会发送完整群历史。**云模型会接收这些片段**；请在群和个人隐私条件允许时启用，敏感内容可用本地端点。模型无工具、不能执行代码/读取密钥/按群文本访问网址；业务处理不抓取任意链接。

`MODEL_DAILY_CALLS` 是持久的上海日期调用次数限额，失败调用也计数；`MODEL_MIN_INTERVAL` 是单 worker 调用间隔，`MODEL_TIMEOUT`、`MODEL_MAX_TOKENS` 与 `MAX_ATTEMPTS` 控制超时/输出/重试。**次数和 token 限额不是按金额的精确硬预算**，需在服务商配置费用上限。错误、无效 JSON、证据不符与日期虚构不会覆盖事件，消息保留在失败列表。非模型错误日志只记错误类型，不写整段聊天或 key。

Pydantic 校验事实、日期与输出结构；未知事实为 null。模型结果须有原文证据；可识别日期的值/精度再次与规则解析核对。不支持的复杂表达保留为待确认，而不编造精确时间。

SQLite 是可恢复队列：pending → processing → done/review/ignored，错误重试后 failed。启动将处理中断项恢复 pending；不会无限重试。没有微服务、向量库或庞大管理后台。

## 日期、更新与人工确认

事件包含标题、类别、组织方、资格、地点、报名方式、链接、联系人、费用、活动状态、个人状态、缺失字段、待确认原因、字段证据与来源。`schedules` 中分别保存 `registration_start`、`registration_deadline`、`material_deadline`、`activity`；活动场次有可空的 end，可记录多个截止/场次；每个条目有稳定 `slot_id`。

- 相对日期使用原消息发送时刻与上海时区，回放“明天”不使用今天。
- 无年份按发送年份做**待确认假设**；无月份按发送月份做待确认假设，不猜跨年。周表达按发送时间所在自然周，保留假设和待确认。
- 只有日期是 `precision=date`，不补 23:59。倒计时仅剩余天数；“今晚”无时刻仍是待确认的日期，不生造精确时刻。
- 报名截止不从活动日期推算。“报名日期尚未确定，25 日比赛”只有活动日期。
- 自动变更仅使用同账号同群的明确引用，或唯一精确赛事名且有“该…”指代/足够完整名称；不会以标题相似跨赛事归并。短变更、重名、关联不足进入候选关联，由你确认。多个同类日期的变更不自动猜要改哪个。
- 锁定字段不被自动覆盖；冲突与锁定阻止的更新留在待确认。详情可以编辑完整 JSON、确认、忽略、修改个人状态或选择部分来源拆分；带版本冲突检查，历史可回溯。请保留现有 `slot_id`，新增条目可设 null 由服务生成。
- 来源撤回只标记来源与提示核对，**不等于取消活动**。只有明确取消通知/人工编辑才改活动状态。已报名只由人工选择。

## 页面提醒与 ICS

首页优先临近截止，支持今日/7天/30天/待确认/已截止、类别与群筛选。缺截止不等于已截止。详情提供原文、图片、群、发送时间、旧日期与字段证据；没有实现 QQ 消息跳转，使用复制原文核对。

月/周日历由免费 FullCalendar 标准模块绘制；◆报名、▲材料、●活动、◇报名开始，加文字图例，不只靠颜色。手机布局有 Chromium 测试覆盖。

页面提醒与 ICS 只对已确认日期生效。ICS 使用 icalendar，稳定 UID、活动版本 SEQUENCE、日期型 VALUE=DATE 与 Asia/Shanghai 时区、精确时间的提前一天 DISPLAY alarm；分别下载报名/材料截止与活动。取消的已确认事件导出 CANCELLED。

**下载导入是快照，未实现订阅端点，不能保证自动同步、替换或删除旧手机提醒**。重新导入与取消更新的行为取决于日历客户端；纯日期没有精确 alarm。默认没有 QQ/其他个人渠道通知，不向班级群发言。

## 数据保留、导出、备份与恢复

数据库、图片、QQ 登录数据和 .env 都不入 Git。API 使用口令 Bearer 或 HttpOnly SameSite=Strict 本地会话；写请求拒绝跨站 Origin；图片与下载也需鉴权，上传同时限制总字节、实际类型和像素。OneBot WebSocket 单独使用自己的 token。

`RETENTION_DAYS` 默认 90：启动及网页手动触发清理过期原文/图片/证据，保留结构化事件。单条原文在详情可删除；若同一事件的证据可能引用该消息，会一并清除该事件历史证据。SQLite 开启 secure_delete 并执行 WAL checkpoint/VACUUM，但不承诺操作系统磁盘层的不可恢复擦除；已经下载的备份由你自行保管/删除。

网页可导出全部 JSON 或下载 SQLite + 图片 zip。备份可能包含群原文，不含 `.env` 或 QQ 登录资料，妥善保管。恢复脚本的数据库完整性、版本、路径穿越和保留旧数据均已测试；恢复前必须停止服务。测试里验证过的恢复命令形式是：

```powershell
py -3 scripts/restore.py ".\schedule-backup.zip" --data-dir ".\data"
```

路径须替换为本机实际路径。恢复前自动在旁边创建 `.before-restore-*` 归档。恢复时应关闭班讯，避免同时写入数据库。

迁移采用 `migrations/001_initial.sql`，启动幂等执行、`schema_version=1`；重复启动已经测试。后续 schema 升级需增加迁移文件并保留旧库备份，不静默删库。

## 代码分层

- `app/qq_plugin.py`：独立只读 QQ 入口，群白名单、连接/成员/普通消息探针、撤回。
- `app/extract.py`、`dates.py`、`models.py`：筛选、模型/离线规则、日期及 Pydantic 校验。
- `app/store.py`、`worker.py`：原消息/队列/事件/版本/锁定/恢复。
- `app/api.py`、`ics.py`：鉴权、四入口、事件操作、原文/图片、数据与日历导出。
- `web/`：轻量中文网页及 FullCalendar，不使用收费日历组件。

可继续改进：真实 NapCat 图片内容/节点只读获取与历史回补须在用户设备上实测；离线规则覆盖有限；人工 JSON 编辑可以进一步换成字段表单；扫描版复杂布局/OCR 质量仍需人工核对。附件解析、手机日历订阅和持久通知调度均未实现，不以“后续功能”代替当前验收。
